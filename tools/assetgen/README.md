# Evolysia asset generator

Requires Python 3.11+, Pillow and numpy. Run from the repository root:

```
python tools/assetgen/build.py palette
python tools/assetgen/validate.py
```

`all` builds every implemented family (palette, terrain, overlays, flora, fauna, people sprites, portraits, early structures, detailed civilisation, wardrobe and landscape). `python tools/assetgen/build.py <family>` builds selected families against the existing master palette. `--seed` controls deterministic texture variation; the authored palette is intentionally invariant across seeds. Builds preserve manifest entries from other families. PNGs use straight RGBA and discrete palette colours. Previews are review-only.

`palette.json` is the runtime slot registry and master colour source. Family generators should read it, select ramp colours and emit reference/index PNGs with identical alpha, metadata and manifest entries. Slot names and indices remain stable when adding new colours: append new slots, never reorder existing ones. LUT images are 256 pixels wide; sample at texel centres without filtering. Merge the chosen rows by their named variable slot groups. Fixed slots must remain unchanged.

The validator checks palette membership, index/reference colour and alpha agreement, hard alpha, dimensions, pivots, metadata, fixed slots, row labels, GPL agreement and preview limits. Terrain adds variant and animation uniqueness, complete corner masks, exhaustive compatible-edge comparisons and seeded random dual-grid tilings. Later phases must add their family-specific acceptance checks before shipping those families.

Terrain sheet columns hold animation frames. Rows hold variants or corner masks, as named in `sheet_rows`; `directions` remains `["none"]`. `frames` is the number of time samples per row. Corner mask bits are TL=1, TR=2, BR=4, BL=8. Mask 0 has no coverage. Index PNGs are data textures; do not apply sRGB decoding to them. Draw materials in `layer_priority` order. Plain tiles are the random full-cell textures; dual-grid corner sheets are sampled on the offset corner lattice.

Overlay columns and rows follow the same layout. Rivers and roads use connection bits N=1, E=2, S=4, W=8; their mask 0 is an isolated pool or patch. Territory and snow use corner bits. Territory masks 0 and 15 are empty because no boundary crosses a homogeneous tile. Culture borders use the appended `culture_white` slot, whose pale reference is mapped by each culture LUT. Overlay validation checks all compatible edge pairs, random connected networks and corner tilings, declared dimensions, frame counts, variation, palette and metadata contracts. Each overlay sheet has a labelled contact sheet plus native views on grass and dark; culture borders include all twelve hues.

Flora sheets contain one state/size each, with variant rows and horizontal animation frames. Use `asset_id` and `state` to select a sheet. `broadleaf_old_bare` is the old-size bare seasonal sheet. Tree wind sway is metadata for the engine shader; grass/reed sway is exported as four frames. Conifer snow caps composite over the matching mature variant using the same pivot and wind displacement. The `fruit` slot group follows the cloth LUT while preserving a red reference colour. Flora checks cover the complete inventory, variant and animation uniqueness, transparent margins, base alignment, colour limits, bare-state foliage exclusion and cap alignment. Contact sheets show every variant/frame, native views on grass and dark, silhouettes and six nature LUT rows.

Fauna sheets each contain one animation, with time across columns and coat patterns down rows. Select the animation by `animation` and the animal by `asset_id` plus `form`. Render side-facing right, mirrored for left. Domestic forms use `coat_lut: lut_hair` for their base coat and preserve fixed light hide patches. Ground pivots stay on the standing foot baseline even during airborne frames. Ambient flock/school pivots are centred. Validation checks the 17 wild/ambient and six domestic forms, complete animation inventory, exact sizes/frame counts, unique frames and coats, margins, palette/index agreement and metadata. Preview sheets show every frame and coat, native views on grass and dark, silhouettes and all eight domestic coat LUT rows. Validation also rejects unregistered PNG outputs, including files left over from an interrupted build.

People sheets each hold one layer and animation. Read `profiles` to find the logical age/build/direction index and `variants` to find the part index. The physical row is `row_lookup[variant_index][profile_index]`; do not infer it by multiplication. Rows are deduplicated. Use that row's horizontal frame, and the logical profile's `hand_anchors` and `row_pivots`. `people/rig.json` records the shared pose data, action IDs, exact layer order and hairstyle pairings. Shaved uses no hair layers. The default elder hair LUT row is 6. A held item includes its grip pixel, aligned with the corresponding body pose.

Assemble people in the declared layer order. Clip body paint to exposed skin (`body_alpha & ~clothing_alpha`) before drawing it after clothing. Mirror side-facing left sprites, anchors and pivots together. Apply chosen skin, hair, cloth and culture LUT groups. The asset build implements this in `people_preview.py` for review; the game renderer uses the newer wardrobe compositor. Frame counts and FPS match section 6.2. Play is child-only; craft, sleep and dead are side-only. Some part layers remain static while the assembled body animates, so unique-frame checks apply to assembled figures rather than requiring hair to twitch in every frame.

People checks cover all 140 layer/animation sheets, exact profiles and part inventories, action mappings, shared-row lookup integrity and uniqueness, reference heights, hand/rig alignment, margins, palette/index agreement and assembled frame uniqueness. Review the animation overview, full profile animation sheets, seven modular part galleries, style selector gallery and skin/hair/cloth/culture recolour sheet. The 48x48 portraits are a separate phase.

Portraits use fourteen static part atlases with 48x48 cells. Select the part variant and age/head-shape profile, then resolve its physical cell through `row_lookup`. Convert the cell index to pixel coordinates using `atlas_columns`; a cell is not necessarily a full PNG row. Identical cells share storage. The manifest declares the frame dimensions separately from atlas dimensions.

`portraits/expressions.json` defines the exact layer order, front/back hair pairing, feature defaults, eleven emotion recipes and subtractive missing-ear scar operation. Genetic eye shape/iris/brow shape choices remain independent of emotion. Composite the hair sublayers at the declared hair position. Apply the missing-ear cutout to ears before compositing that part. Clip paint to the visible skin index group after scars, and apply the selected skin/hair/cloth/culture LUT groups. Default elder hair uses LUT row 6. `portrait_preview.py` implements the assembly for review; portrait integration remains unfinished.

Build with `python tools/assetgen/build.py portraits`, then validate normally. Portrait checks cover every part/profile variant, unique physical atlas cells, frame sizes, colour limits, margins, the exact expression recipes, eleven distinct expressions per head profile and missing-ear cutout overlap. Review all-age expression sheets, head/feature/style galleries and all skin, hair, cloth and culture LUT rows. Native strips show the portrait without its vignette on grass/dark and as a silhouette.

Build early complete structures with `python tools/assetgen/build.py structures`. Eighteen structure IDs have building, complete, damaged, ruined and burned sheets. Fire pit, kiln and smelter also have four-frame lit strips at 6 fps. Select by unchanged `asset_id`, structural `state` and `lighting`; lit sheets have state `complete`. Files use `<asset_id>_<condition>` or `<asset_id>_lit`. Every sheet includes reference and index PNGs, even when all its materials use fixed slots.

Structure metadata declares materials, footprint pivots and engine shadow classes. `emissive_slots` identifies the fire ramp; kiln and smelter `fire_window` bounds contain the animated opening, with the outer masonry unchanged. The totem has culture-tinted carved grain and a reserved 12x12 `glyph_anchor`; `glyph_generated: false` means there is no authored culture symbol. Glyph production and rejection checks belong to section 9. Modular walls, roofs, fences, pens, docks and bridges belong to the following section 7.2 phase.

Structure checks cover all 93 sheets and 102 frame images, exact state/size inventory, unique conditions and lit frames, colour budgets, margins, footprint alignment, material metadata and contained furnace flames. Review the two overviews and eighteen condition sheets, including native grass/dark/silhouette strips, all lit frames and twelve totem culture LUT rows. Ground shadows, smoke, glow and game-side assembly are supplied separately.

The additive `civilisation` family introduces authored 64 px close artwork and 32/16 px density levels on the same logical grid. It supplies modular rooms, separate props, visible inventories, specialist layouts and early/modern/future samples. Existing files and simulation IDs remain unchanged. See [CIVILISATION.md](CIVILISATION.md) for scale, roof, storage, transport and coverage contracts, including the remaining work. The review examples demonstrate the art contract. Current game integration and its limits are documented in [Art and customisation](../../docs/wiki/Art-and-customisation.md).

Build `civilisation wardrobe landscape` together for the expanded kit. The wardrobe supplies 185 part selections, independent per-piece main/trim dyes, 32 editable outfit presets and all twenty shared-rig animations at every density. Its packed animation strips use `strip_columns` and density-specific `row_lookup`. Landscape supplies 56 materials, complete corner transitions, plain variants and eight cliff types at every density. All new components preserve palette/index contracts and add their own acceptance checks. Build before validation; do not run the validator while a build is rewriting sheets and sidecars.
